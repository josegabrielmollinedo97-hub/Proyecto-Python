# Reflexión sobre la transformación del sistema de librería a POO

Al realizar la transformación del sistema de inventario y ventas de una librería a programación orientada a objetos, pude comprender que las clases permiten organizar mejor las partes de un programa. En el primer proyecto se utilizaron funciones, listas y diccionarios para registrar libros, buscar productos, controlar existencias y guardar las ventas. En esta nueva versión esas tareas se distribuyeron en clases que representan los elementos principales del negocio.

La clase Producto reúne los datos de cada libro, como código, nombre, categoría, precio y stock. La clase Inventario se encarga de administrar los productos, mientras que Venta representa una operación de compra. También se separó el trabajo de guardar y leer los archivos CSV en la clase PersistenciaCSV. Esta organización permite encontrar más fácilmente dónde realizar cambios y evita concentrar todas las instrucciones en un solo archivo.

Uno de los conceptos aplicados fue el encapsulamiento, porque los atributos del producto se manejan mediante propiedades. También utilicé herencia al crear LibroFisico y LibroDigital a partir de Producto. La abstracción se representa con la clase Registrable, que establece un método que deben implementar sus clases concretas. El polimorfismo se observa cuando cada tipo de libro puede mostrar su descripción de una manera diferente.

Se conservó una regla importante del primer proyecto: cuando un libro tiene tres unidades o menos, el sistema muestra una alerta de stock mínimo y registra el aviso en la bitácora. Además, al registrar una venta se comprueba que exista suficiente inventario para evitar cantidades negativas. Los datos continúan guardándose en archivos CSV para que permanezcan disponibles al cerrar el programa.

Las pruebas automáticas ayudan a comprobar que se puedan buscar productos, rechazar códigos inválidos, impedir ventas superiores al stock y guardar y cargar información. Considero que esta versión está mejor organizada y es más fácil de ampliar. Como mejoras futuras se podría agregar una interfaz gráfica, usuarios con contraseñas y reportes exportables. Este proyecto me permitió practicar los principios de POO y entender cómo se pueden aplicar a un problema cotidiano como administrar una librería.
